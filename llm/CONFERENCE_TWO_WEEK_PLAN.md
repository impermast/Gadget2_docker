> Редакция 2026-10-10. План будущей кампании, не команда на её запуск.
> Автономия и разрешения: `llm/CODEX_AUTONOMOUS_PROMPT.md`.

## 1. Вопрос, область вывода и приоритеты

Исследуем, может ли феноменологическая dSIDM в изолированном карликовом NFW-гало
образовать устойчивую тонкую вращательно поддерживаемую структуру в доступном
временном интервале. Область: N=10^5, существующие вращающиеся IC, сравнение
CDM/SIDM/dSIDM. Это ограниченный численный эксперимент, не общий запрет или
доказательство образования тёмных дисков.

Приоритеты: достоверность и прослеживаемость → готовый доклад к сроку →
обязательная согласованная T=5 проверка → дополнительные эксперименты.
Отсутствие диска, численная патология и недостаточность данных — разные исходы.
Гипотезу об отсутствии диска можно опровергнуть; заранее готового вывода нет.

Номинальный spin_k не равен измеренному Jz, безразмерному spin λ или гарантии
равновесия. Проверь реализацию `add_halo_rotation.py`, знак вращения, систему
единиц и исходные скорости; сохраняй nominal/measured отдельно. При проблемах
IC не переписывай старые файлы: зафиксируй ограничение и оцени пригодность контролей.

Прежняя T=5 группа — самостоятельный контекст при иных spin_k и σ/m.
Она не заменяет matched T=5 k08 controls. Прежние численные оценки и заявления
о runaway — подсказки для повторного анализа, не числа для слайдов без locator.
Ранний минимум c/a около t=0.1 не является доказательством устойчивого уплощения;
связь с релаксацией IC проверяй по временным рядам и контролям.

## 4. Научная последовательность

### A. Аудит и анализ существующих серий

Зафиксируй параметры, доступные снапшоты и код анализа. Добавь Jz и provenance
по техническому плану, затем анализируй шесть k08 T=2 и пять k05 T=5 серий.
У частичных серий записывай реально достигнутое время. Исходные симуляции
повторно не запускай. При недостающих CSV вычисли их из существующих данных.

До обсуждения новых результатов зафиксируй критерии и окна анализа:

- апертура r<5 в подтверждённых физических kpc, частицы PartType3;
- единый центр, система отсчёта скоростей и исходная ось z;
- c/a, z_rms/R_rms, |Vrot|/σ, Jz, масса апертуры и jz=Jz/M;
- NInteractions с проверенной семантикой счётчика, доля затронутых частиц,
  минимальный положительный Systemstep по полному логу, плотность ядра;
- late-time окно T=2: [1,2]; T=5: [2.5,5] в code time; для частичной серии —
  пересечение с доступным интервалом, без подмены окна последним снапшотом;
- при менее трёх конечных значений в окне ставь insufficient_coverage для
  late-time вывода; отдельное final-значение показывать можно;
- при сравнении T=2 с T=5 используй общее окно [1,2], а длинную эволюцию
  показывай отдельно. T из параметров не называй Gyr без проверки конверсии.

Для первичного screening зафиксируй существующие пороги из classify_series:
c/a<0.45, z_rms/R_rms<0.35, |Vrot|/σ>0.6. Это эвристика, не универсальное
определение тонкого диска. Для кандидата требуется одновременное выполнение
критериев хотя бы в трёх последовательных late-time снапшотах, без выявленной
патологии; укажи длину покрытого интервала. Экстремумы, взятые в разные моменты,
нельзя объединять в «устойчивый диск». Сохраняй сырой verdict классификатора
и отдельную интерпретацию кампании. Более слабое уплощение описывай количественно.

Systemstep<1e-6 — диагностический флаг, не автоматическое доказательство
физического коллапса или единственная причина для уничтожения/остановки данных.
Разделяй жизненный статус прогона и качество численного решения.
Изменение Jz внутри r<5 может быть вызвано переносом массы через апертуру:
для утверждения о глобальном сохранении нужен отдельный глобальный контроль.
Шум оценивай по controls/доступной чувствительности; без независимых seed/resolution
проверок не заявляй статистическую значимость и сходимость.

### B. Проверка диссипации

Прочитай реально используемую версию `/opt/gizmo-public/sidm/sidm_core.c`,
функцию `calculate_interact_kick`, и проверь активную сборку/compile flags.
Зафиксируй source hash и связь с бинарником; чтение исходника само по себе
не доказывает, что именно он скомпилирован.

Для kick_velocity=0 и 0≤D≤1 из |v_rel'|=(1−D)|v_rel| следует положительная
доля потери относительной кинетической энергии в СЦМ:
`loss_fraction=(E_rel_before−E_rel_after)/E_rel_before=2D−D²`.
Это не отношение изменения полной энергии гало. При ненулевом kick используй
полную формулу из кода, не ту же кривую 2D−D².

Обязательный минимум: аналитический вывод, Python pairwise-тест, проверка
импульса, исследование углового момента и документированный аудит реализации.
Не требуй, чтобы angular momentum residual обязательно был ненулевым в каждом
испытании: специальные геометрии дают ноль. Оцени изменение и зависимость от
геометрии/случайного направления, не называй его заранее физическим эффектом.

Проверка выполняемого GIZMO — отдельный условный этап после аудита наблюдаемых
величин и разрешения на короткий тест. Предпочтителен изолированный минимальный
эксперимент в новом run-каталоге; задаются начальные данные, событие, допуск и
критерий сравнения. Снимок полного гало с гравитацией/множественными рассеяниями
не позволяет сам по себе проверить отдельное столкновение. Если нужных данных
нет, поставь `not_validated_in_solver`, сохрани ограничение и продолжи доклад.
Python-проверка не считается проверкой исполняемого бинарника.

Не останавливай production T=5 ради этой проверки. Возможность `--resume`
требует реальных restart-файлов и проверки механизма конкретной сборки.
Отсутствие параметра TimeBetRestartFile в шаблоне не доказывает отсутствие
restart по stop-file/лимиту; такой вывод нельзя делать по одному grep.

### C. Целевой T=5 блок: spin_k=0.8, σ/m=2.5

Четыре запуска с одной IC, N=10^5, cadence=0.1, MaxSizeTimestep=0.005,
kick_velocity=0, 8 MPI; остальные численные настройки сверяются между modes,
включая реально применяемое к PartType3 softening. Не ограничивай сверку
полем SofteningHalo. Прежний CDM T=2 использовал иной max-step: это укажи
как ограничение, а не незаметно смешивай с новыми controls.

Новые имена содержат spin-суффикс, чтобы избежать коллизий с прежними k05 T=5:

| Run ID в dsidm_spin_k08_transition | Режим |
|---|---|
| cdm_N1e5_T5_k08 | CDM |
| sidm_s2p5_N1e5_T5_k08 | упругий SIDM |
| dsidm_s2p5_D0p25_N1e5_T5_k08 | dSIDM D=0.25 |
| dsidm_s2p5_D0p50_N1e5_T5_k08 | dSIDM D=0.50 |

Ниже шаблоны preflight, выполнять только в запущенной кампании после проверки
CLI. Финальные команды и resolved параметры сохранить перед запросом разрешения:

```bash
# Host, Bash; контейнерные пути используются только внутри docker exec.
common=(--ic-file /nbody/ics/dwarf_rot_N1e5/dwarf_rot_N1e5_k08
        --time-max 5 --time-bet 0.1 --first-snapshot 0
        --mpi-procs 8 --max-step 0.005 --kick 0
        --time-limit 14400 --skip-viz --no-tg)

docker exec gadget-gizmo bash /nbody/scripts/run_sim.sh --name dsidm_spin_k08_transition/cdm_N1e5_T5_k08 --type cdm "${common[@]}" --dry-run
docker exec gadget-gizmo bash /nbody/scripts/run_sim.sh --name dsidm_spin_k08_transition/sidm_s2p5_N1e5_T5_k08 --type sidm --sigma 2.5 --dissipation 0 "${common[@]}" --dry-run
docker exec gadget-gizmo bash /nbody/scripts/run_sim.sh --name dsidm_spin_k08_transition/dsidm_s2p5_D0p25_N1e5_T5_k08 --type sidm --sigma 2.5 --dissipation 0.25 "${common[@]}" --dry-run
docker exec gadget-gizmo bash /nbody/scripts/run_sim.sh --name dsidm_spin_k08_transition/dsidm_s2p5_D0p50_N1e5_T5_k08 --type sidm --sigma 2.5 --dissipation 0.50 "${common[@]}" --dry-run
```

Предлагаемый, ещё не одобренный бюджет: до 4 часов wall-time на run, до 16 часов
на блок, по одному запуску на 8 MPI. Старые времена счёта — только ориентир;
k05 не гарантирует runtime k08. Диск оцени по размерам аналогичных снапшотов:
около 51 снапшота/run при t0=0, плюс логи, анализ и запас. RAM/дисковый лимит
и аварийный резерв зафиксируй перед одобрением, не делай неограниченную очередь.
Точное штатное действие для остановки своей задачи при лимите/исчерпании диска
включи в то же согласование. Новый run должен оставлять время на анализ до freeze;
при нехватке времени предложи частичный пакет, а не увеличение бюджета молча.

После разрешения запускать согласованные команды без `--dry-run` последовательно.
`--no-tg` оставлять при отсутствии разрешения на уведомления; при одобренном TG
заранее включить в команды `--tg-progress --tg-interval 30` вместо него.
`--skip-viz` отключает legacy постобработку; анализ выполняется каноническим runner'ом.

Перед каждым запуском сверять отсутствие занятого CPU/целевого каталога,
неизменность одобренных параметров и оставшийся бюджет. При существующем каталоге
сначала восстановить его статус, не перезаписывать и не создавать дубликат молча.
Проверить механизм штатной остановки своей задачи до запуска; TimeLimitCPU
не считать гарантией остановки зависшего процесса. Без проверенного мониторинга/
лимита unattended запуск не готов. Не убивать чужие процессы и не перезапускать контейнер.

По завершении: `check_run.py --run-root ... --mode summary` → серия метрик →
`check_block.py --group-root ...` → manifest. Проверять фактическое время и
данные, не только exit code. Исчерпание лимита означает incomplete, если TimeMax
не достигнут. Автоматического повторного запуска, увеличения лимита или resume нет.
После неожиданной ошибки сначала классифицировать причину. Следующий одобренный
run разрешён, если ошибка локальна, ресурсы в норме и результат сравним;
при общей проблеме сборки/IC/диска остановить очередь, сохранив остальные задачи.

### D. Опциональный cross-section check

Только после обязательных доступных этапов, отдельного одобрения и при запасе
времени до freeze: k08, T=2, σ/m=5, три режима SIDM D=0, dSIDM D=0.05 и D=0.10.
Подготовить matched настройки и уникальные имена с k08. При дефиците времени
поставить deferred с причиной; новый σ/m=10 скан и повтор D=0.75 не делать.

## 5. Фигуры и выступление

План основных фигур: совместная эволюция shape/thickness/rotation; Jz/Jz0 и
jz/jz0 с массой апертуры; NInteractions и timestep; morphology/profile comparison.
Используй существующие registry-plots/runner'ы, расширяя их по необходимости.
Каждую цифру связывай с claims.csv. PNG визуально проверяй доступным инструментом:
подписи, единицы, legend, масштабы, clipping. Если просмотра нет — отмечай
visual_review_pending, не заявляй, что просмотр состоялся. GIF не заменяет метрики.

Черновик слайдов делай рано, до завершения всех расчётов. Предлагаемая история:
вопрос → модель и IC → определения критериев → controls → результаты →
численные ограничения → вывод в исследованной области → следующие шаги.
Каждый основной слайд содержит один тезис и источник evidence; незавершённые
расчёты помечены. Подготовь сокращаемые слайды/backup для другого регламента.

В notes укажи целевое время по слайдам, переходы и понятное устное объяснение
D, spin_k, kick_velocity, Jz и численной патологии. Q&A должен включать:
нормировку D, равновесие IC, сохранение момента, апертуру, controls, N/softening,
сходимость, позднее формирование и ограничения отрицательного результата.
Подкрепляй внешние научные утверждения первичными источниками, отделяя их от
результатов собственной кампании.

Предусмотри две репетиции пользователя: первая — связность и длительность,
вторая — финальный регламент и вопросы. Агент готовит сценарий и обрабатывает
полученную обратную связь; без фактического прогона человеком пишет pending.
Оценка длительности по тексту — только estimate.

## 6. Сроки, freeze и передача

D-0 — подтверждённая дата выступления. При меньшем запасе сокращай опциональные
исследования, не проверку достоверности и не время на слайды.

| Интервал | Результат |
|---|---|
| D-14…D-12 | аудит, контракты метрик/manifest, baseline, черновая структура слайдов |
| D-12…D-7 | анализ существующих серий, pairwise A, согласованный T=5 блок |
| D-8…D-5 | обновление таблиц/фигур, проверка выводов и ограничений, Q&A |
| До D-3 | только при запасе — опциональный блок; первая репетиция |
| D-3 | freeze доказательной базы для основных слайдов; прекращение новых production-запусков |
| D-3…D-1 | финальные слайды/экспорт, notes, проверка источников, репетиция |
| D-1…D-0 | только исправления достоверности, читаемости и тайминга |

Freeze не означает скрыть ошибку: существенное опровержение включи с записью
изменения. Поздние дополнительные результаты идут в backup, если их нельзя
проверить к сроку. При неполном T=5 сформулируй честный вывод по доступному T,

Передача включает пакет, таблицу готовности, ограничения, команды воспроизведения,
